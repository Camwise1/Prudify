# Review — August 2026

Five independent review passes over the published code: security, container
and ops, UI/UX, architectural generality, and ecosystem integration. Findings
are ranked by what they cost a real user, not by how interesting they are.

Everything in **Fixed** is already committed. Everything below it is a
backlog, ordered.

---

## Fixed

### Authentication bypass — critical

`main.py` served the SPA through a catch-all route that joined the request
path onto the static directory with no containment check. The route is
unauthenticated of necessity: the app shell has to load before anyone can log
in.

`Path("/static") / "/config/config.yaml"` discards the left operand entirely —
that is how `pathlib` works — and neither uvicorn nor Starlette resolves `..`
first. So `GET //config/config.yaml` returned the config file, which holds the
API key in cleartext. Anyone who could reach port 8317 could read it.

That is not merely a file read. With the key, the settings API accepts
`whisper_cpp_binary`, an arbitrary executable path that the transcriber then
runs. Unauthenticated request → API key → remote code execution, as root.

Paths are now resolved and required to stay inside the static tree, with
regression tests covering absolute paths, dot segments and encoded traversal.

### API key written to three places, one of them an API — high

The key was logged at startup. The root logger writes to the console, to a
rotating file on the config volume, and to a database table that the API
serves back at `/api/v1/system/logs`. The secret was therefore published
through the interface it protects, it went wherever `docker logs` went, and
rotating the key left the old one readable. The README told people to
`grep "API key"` out of the container log.

Startup now points at `prudify config --reveal-key`.

### A non-English wordlist silenced the entire book — critical

`compact()` was `re.sub(r"[^a-z0-9]", "", text)`, which returns `""` for any
non-Latin token. A Cyrillic rule installed an empty-string key in the
exact-match table; every Cyrillic word also compacted to `""`; so every word
matched. Verified before fixing:

```
rule: 'блядь'
input: "привет мама я дома хорошо"
matched: привет, мама, я, дома, хорошо      ← every word
```

The whole audiobook came out silent, with no error. Meanwhile the README
invited non-English users to add their own list. Now Unicode-aware, with
empty keys guarded, and tests in Cyrillic and Greek.

### A dry run reported books as cleaned — high

```python
part.status = (
    BookStatus.CLEANED.value if not result.skipped else BookStatus.CLEANED.value
)
```

Both branches identical. The cautious user who previewed first watched their
library turn green and then found an empty output folder. Dry runs now leave
books in `New`.

### `latest` was never published — blocking

`type=raw,value=latest,enable={{is_default_branch}}` compares the ref against
the default branch name, and on a tag push the ref is `refs/tags/v1.0.0`. It
is always false. Every document — README, install guide, compose file — told
users to pull `:latest`, which would never exist. Now keyed off the tag
itself, excluding prereleases.

### The image ran as root, with PUID/PGID documented but not implemented

`grep -rn "USER|PUID|PGID|gosu"` returned nothing outside the docs. Every
cleaned file landed `root:root`, so Plex and Audiobookshelf could read the
results but not rename, retag or delete them — the classic self-hosted
papercut, and the top complaint category for this kind of app. The Unraid
section of the install guide described a feature that did not exist.

Now a real entrypoint with `gosu`, honouring `PUID`/`PGID`/`UMASK`.

### The GPU block made the compose file invalid

`extends: prudify` inherits `container_name`, so uncommenting it produced
`container name "prudify" is already in use` and **the whole file failed to
parse** — including the CPU service. It also promised acceleration the image
cannot deliver: `python:3.11-slim` has no CUDA runtime, and `device: auto`
would select `cuda` as soon as an NVIDIA runtime was passed through, then fail
at model load part-way into a job. Removed, with an honest note.

### Smaller container fixes

Dependency install moved above the source copy, so editing a `.py` no longer
reinstalls ~1 GB of ML wheels — which matters enormously when arm64 builds
under emulation. `tini -g` so in-flight ffmpeg children get SIGTERM.
`stop_grace_period: 60s`. Scratch renders on a named volume instead of the
config bind mount. OCI labels. Dropped `VOLUME`, which silently creates
orphaned anonymous volumes for `docker run` users.

## On replacing the API key with OAuth

**Recommendation: don't.** Not as stated, and not next.

First, the precision point: for a single-user LAN app, "implement OAuth"
almost always means *becoming an OIDC relying party* — delegating login to
Authelia, Authentik or Keycloak. That is a different and much smaller job than
implementing OAuth, and worth naming, because neither one fixes anything that
was actually wrong here.

What comparable tools do, without exception:

| | Primary auth | Programmatic | Identity provider |
| --- | --- | --- | --- |
| Sonarr / Radarr | Forms login, session cookie | Static `X-Api-Key`, kept forever | None — people front it with Authelia |
| Audiobookshelf | Username + password → JWT cookie | Per-user API token | OIDC added later, as an *option* |
| Jellyfin | Username + password | API keys | LDAP/SSO via plugins |

Local username-and-password login is primary everywhere. A long-lived API key
survives alongside it for scripts. OIDC, where it exists at all, is a bolt-on
for the minority already running an identity provider. Nobody makes it the
only door, and nobody at this scale implements an OAuth server.

The deeper point: **this app did not have an authentication-mechanism problem.
It had an authentication-bypass problem.** A traversal that hands out
`config.yaml` defeats API keys, passwords, sessions and OIDC identically.
Shipping OAuth on top of that would have been security theatre.

What to do instead, in order:

1. **Session-cookie login with a username and password.** Argon2id hash in
   `config.yaml`, `HttpOnly; SameSite=Lax` cookie. This is the high-value
   change: it gets the key out of `localStorage` where any future XSS reads
   it, out of the SSE URL where reverse proxies log it, and gives you logout
   and rotation. Add a CSRF check, since cookies reintroduce that exposure.
2. **Keep the API key** for cron, the CLI and Home Assistant. Enforce a
   minimum length, and scope the `?apikey=` fallback to the SSE route only —
   it currently authenticates *every* endpoint, including the one that returns
   the key itself.
3. **Trusted-proxy header auth** as an explicit mode, honoured only from
   configured CIDRs. About forty lines, and it gives the Authelia/Authentik
   crowd real SSO without this app knowing anything about OAuth.
4. **Native OIDC only if people ask**, and only *in addition to* local login —
   otherwise a misconfigured provider locks you out of your own audiobook
   server.

## Backlog

### P1 — correctness and data integrity

**`docker stop` cannot interrupt a transcription, and losing the race corrupts
files.** `transcribe_file` takes a `cancel` callback but only checks it in the
chunked branch; the default path ignores shutdown entirely, so a 20-hour book
runs to completion or gets SIGKILLed. Worse, when shutdown *does* win, the job
is marked `CANCELLED`, and `_requeue_orphans` only recovers `RUNNING` jobs — so
a graceful restart silently drops work that a hard kill would have resumed.
And `render` stages to the work dir then `shutil.move`s across filesystems,
which degrades to copy-then-unlink; a kill mid-copy leaves a truncated `.m4b`
in the clean library that `skip_if_output_exists` then never retries. That is a
permanently corrupt audiobook. Check `cancel` in the segment loop, distinguish
shutdown from user cancel, and write to a `.partial` sibling on the
destination filesystem then `os.replace`.

**Settings mutate mid-queue.** `update_settings` mutates the same `Config`
object the queue holds, so changing the wordlist with 300 books queued
silently changes what the rest of the batch does. Snapshot filtering,
transcription and output settings into the job at enqueue time, and record the
wordlist name and model in the output tag — for a tool whose value is "I trust
this file", provenance is the wrong thing to lack.

**The free-space guard checks the wrong filesystem.** It measures the output
mount; the WAV and staged render go to the work dir. A full work volume is
never detected — it surfaces as a generic ffmpeg failure. Also, work
directories leak on every SIGKILL and nothing prunes them.

**`OMP_NUM_THREADS` is a placebo.** CTranslate2 honours it only when
`intra_threads` is 0, and the code always passes an explicit `cpu_threads`. So
the documented knob does nothing, in a compose file that explains at length how
to tune it. Make the env var the default for the setting.

### P2 — the things that would most improve adoption

**Ship the transcript.** This is the strongest finding in the review. The most
expensive artifact the system produces is written to disk, exposed on a REST
route that the frontend never calls, and otherwise discarded. `plain_text()`
exists and is called from nowhere. An SRT/VTT/TXT serialiser is about sixty
lines over data you already have. It changes the product from "profanity
filter" to "transcribe and optionally filter your audio library", which is a
much larger audience — including people who want nothing filtered at all.

**A preview, and a way to verify.** There is no way to see what *would* be
muted before committing, and no way to check what changed afterwards — no
player, no download, no surrounding sentence for a match. The matches table
shows word, timestamp and confidence, but not the line it came from, which is
the only thing that lets you judge a false positive. The transcript endpoint
that would fix this already exists and is unused.

**Per-library settings.** `libraries` is a list with full CRUD, but filtering,
transcription and output are global. "Kids' library on strict + mute, mine on
moderate + beep" is impossible. This is the biggest gap between what the config
looks like it supports and what it does.

**Failed scans are reported as successes.** A missing source path returns
`{"error": ...}` with no `total`, and the UI toasts *"Scanned: undefined
book(s)"* in green. This is the most likely first-run failure — a typo, or a
NAS share not mounted yet — and the UI actively tells the user it worked.

**No mobile navigation at all.** The sidebar goes off-canvas below 780px and
the only control that reopens it is hard-coded `display: none`. The state and
CSS both exist; the button was never wired up.

**The destructive action has no confirmation, and a harmless one does.**
"Delete clean copy & reset" unlinks rendered files with no prompt, sitting
where Cancel usually lives — while removing a library, which touches nothing on
disk, does confirm.

### P3 — worth doing eventually

- **Per-rule actions and categories.** A rule has no action; output mode is one
  global setting. Beeping slurs while muting swearing is impossible. This is the
  actual unlock for "parental controls" more broadly, and it lets the community
  ship lists without you curating them.
- **Spoken-content search.** Transcripts are already on disk, keyed per part.
  SQLite ships FTS5. Roughly 150 lines for something nothing else in this space
  does — and you are already paying the storage cost with none of the benefit,
  since nothing prunes the transcript directory.
- **Accent folding is wrong outside English.** `año` → `ano`, `coño` → `cono`.
  A Spanish list containing `ano` mutes every occurrence of "year". Make
  mark-stripping per-language.
- **Non-English defaults.** `base.en` cannot transcribe anything else at all.
  Default to `base` with auto-detect; keep `.en` as a documented optimisation.

### Cut

- **`openai-whisper` backend** — strictly dominated by faster-whisper, by your
  own README. Two backends is enough.
- **Chunked transcription** — ~55 lines plus a disk cache for a scenario the
  README says faster-whisper makes unnecessary.
- **`leet_normalise`** — Whisper transcribing speech does not emit `sh1t`.
  Habit imported from text filtering.
- **`mirror_structure`** — written to every user's config, read by nothing.
- **Dead columns** — `Book.duration` is never assigned; `Job.stage` is only
  ever `""`, and the UI renders against it.
- **`extra_words`** — a per-call hook no caller supplies.

## Integrations

Researched against current documentation rather than memory.

**Libation — build nothing.** It has no plugin system and no post-download
hook; it is a thing you drive by cron, not one that calls out. The handoff
already works: Libation writes an m4b, the watcher sees it, the 30-second
stability gate stops it grabbing a half-written file. The only alternatives are
shelling out to its CLI (which drags Audible credentials into the threat model)
or reading its database (undocumented, and it has already changed backends).
Worth documenting; not worth coding.

**Audiobookshelf — one thing worth building, one trap.** ABS has no outbound
webhooks and no "book added" event, so an ABS-triggered flow cannot be built at
any price. The custom metadata provider spec is search-only — wrong shape.

The important finding is a **caveat the README should carry and doesn't**: ABS
keys progress on `libraryItemId`, and a copy in a second library is a different
item. Two libraries means two independent progress records for the same book —
switch from the original to the cleaned copy and you restart at zero. There is
no native fix; the only known workaround is raw SQL, and it doesn't stay
synced. Note the asymmetry: `mute` and `beep` preserve the timeline, so a
one-shot progress transfer would at least be semantically sound; `cut` shifts
it, so it never can be.

Continuous progress sync is the trap — polling forever, one API key per
household member, conflict resolution you'd get blamed for.

**Plex and Jellyfin — docs only.** Both offer a one-line scan trigger and
nothing else useful. Audiobook support in both has been second-class for a
decade; people who care run Audiobookshelf.

**What to expose instead.** Sonarr and Radarr ship a generic webhook plus
Apprise, and notably **no `/metrics`** — the ecosystem built external exporters
against their REST API. The lesson is consistent: a stable REST API and one
outbound webhook is what you owe integrators; the community builds the rest.

Ranked:

1. **Document the ABS progress caveat.** Twenty minutes, highest value per
   minute in this document.
2. **Generic outbound webhook** on job finished/failed. The event bus already
   publishes these. One implementation buys ABS scan triggers, Plex partial
   refresh, Jellyfin, ntfy, Home Assistant, and anything not yet imagined.
   Include the output path — that's what makes Plex's `?path=` form usable.
3. **`docs/integrations.md`** with copy-pasteable recipes built on the webhook.
4. **Optional Apprise notifier.** One dependency, ~50 lines, covers Pushover,
   ntfy, Discord, Gotify, Telegram. People want telling when an 18-hour
   transcription finishes.

Don't build: any Libation integration, an ABS metadata provider, continuous
progress sync, `/metrics`, or a Home Assistant component.

## What already holds up

Worth recording, since a review reads as a list of faults.

No shell anywhere — three subprocess call sites, all list-form, no
`shell=True`. **There is no command injection**, including through filenames,
tags, codecs or the filter graph, and I checked each specifically. Wordlist
text never reaches ffmpeg; only floats do. SQL is parameterised throughout. No
`dangerouslySetInnerHTML`. The wordlist editor's `_safe_name` genuinely
contains traversal, and output paths cannot escape the library root. CI uses
`pull_request`, not `pull_request_target`.

The Settings page is better than the brief expected — six tabs, plain-English
hints on nearly every non-obvious control, output modes labelled by consequence
rather than jargon. The wordlist tester is the best-designed thing in the app:
a default sample containing "Scunthorpe", inline highlighting, and the
allowlist explained with a one-click route to edit it. Empty states name the
next action rather than sitting blank. SSE with a polling fallback and
server-side heartbeats is the right architecture for hour-long jobs behind a
reverse proxy.

And the "originals are untouched" promise is both stated and actually enforced
in code.
